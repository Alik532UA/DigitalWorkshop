## Архітектурний стек
- **Framework:** SvelteKit 2 + Svelte 5 (Runes)
- **Language:** TypeScript
- **Styling:** Vanilla CSS (заборонено TailwindCSS без прямої вказівки)
- **Deployment:** GitHub Pages (OIDC-based CI/CD)

## Стратегія `data-testid` у production

**B — зберігати.** Плагіна, який вирізав би атрибут на етапі збірки, у проєкті
немає, отже де-факто вибрано B — і це записано, а не вдається за A
(TESTID-AND-NAMING-v8 § 1.11). Наслідки, з якими це рішення живе: локатори видно
у продакшн-версії (+0,5–2 КБ gzip і видима внутрішня структура), зате
smoke-тести можна писати проти живого сайту без окремої staging-збірки.

Якщо колись з'явиться плагін видалення — атрибут прибирається **лише** при
`mode === 'production'`, а для `staging`/`preview` лишається, і цей розділ
оновлюється разом із кодом.

## Ключові патерни та правила

### 1. Controller Pattern (Бізнес-логіка)
- Уся логіка стану та побічних ефектів винесена в класи-контролери у папці `src/lib/controllers/`.
- Файли мають розширення `.svelte.ts`.
- Компоненти `.svelte` відповідають лише за UI та пропси.

### 2. Storage Facade (Ізоляція сховища)
- **КРИТИЧНО:** Пряме використання `localStorage` або `sessionStorage` ЗАБОРОНЕНО.
- Використовуй `storage` сервіс із `$lib/services/storage`.
- **Namespace:** Усі ключі автоматично отримують префікс `digitalworkshop_`. Це необхідно для запобігання колізіям на спільному домені `github.io`.
- **Фасад ніколи не кидає.** `set()` і `setJSON()` повертають `boolean`; `false`
  означає, що значення не збережено (квота, приватний режим). Код, для якого
  збереження критичне, це перевіряє — решта ігнорує, і це нормально.

### 3. Реактивність (Svelte 5 Runes)
- Використовуй `$state`, `$derived`, `$effect`.
- Заборонено використання застарілих Stores (`writable`, `readable`).
- Ефекти (`$effect`) повинні завжди повертати функцію очищення для таймерів або підписок.

### 4. Конвенції іменування
- Компоненти: `PascalCase.svelte`
- Контролери: `NameState.svelte.ts` (класи всередині — `NameState`)
- Сервіси: `name.ts` (чисті функції або об'єкти)

## НЕ РОБИ (Anti-patterns)
- Не використовуй `on:click` (використовуй `onclick={...}`).
- Не використовуй `<slot />` (використовуй `{@render children()}`).
- Не створюй бізнес-логіку всередині `.svelte` файлів.
- Не роби `commit` без прямої вказівки користувача.
- Не роби `push` самостійно.

## Приклад правильного контролера
```typescript
import { storage } from '$lib/services/storage';

class FeatureState {
    value = $state(storage.get('feature') || 'default');

    constructor() {
        $effect(() => {
            storage.set('feature', this.value);
        });
    }
}
```

|---|---|
| Два конфіги обіцяють різні порти | `.claude/launch.json` **цього** проєкту каже `5174`, а кореневий у теці `GitHub` — `dw-dev` на `5198`. Перед запуском подивись, який із них піднявся, інакше відкриєш не те |
| `base` тут **завжди** `/DigitalWorkshop` | у `svelte.config.js` він захардкоджений, винятку для dev немає. Тобто dev-сервер віддає застосунок за `/DigitalWorkshop/`, а не за коренем |
| Сорок дві локалізації | правка одного ключа означає правку сорока двох файлів. Перед додаванням перевір, чи ключ уже не існує |
| Playwright тут **не стоїть** | `playwright.config.*` у проєкті немає. Не створюй файлів під нього — вони не запустяться, і ніхто про це не повідомить (AI-AGENT-PITFALLS-v8 § 1.3) |
| Правка `src/app.html` міняє хеш CSP | хеш скрипта першого кадру рахується з файлу в `svelte.config.js`, тож розійтися не може — але скрипт мусить лишатися ПІСЛЯ `%sveltekit.head%`, інакше політика його не покриває. `unsafe-inline` у `script-src` не повертай: за його наявності SvelteKit не додає хешів узагалі |
| Кільце фокуса — `--focus-ring`, не `--accent-primary` | акцент ставить `+layout.svelte` інлайном, тож поза макетом (сторінка помилки) змінна неоголошена й `outline` стає невалідним — кільце зникає |
| Новий гейт, що читає власні джерела, бере `withoutComments()` з `src/test-support/source-text.ts` | поруч із кожною забороною стоїть коментар, який її ЦИТУЄ, тож без відрізання перевірка червоніє на власному поясненні. Копій цієї функції в проєкті вже було чотири, і кожна давала хибний вердикт. П'ятої не пиши |
| Регулярка по рядках файлу — `split(/\r?\n/)`, а не `split('\n')` | `.gitattributes` тримає `eol=lf`, але в старому checkout робоче дерево може бути з CRLF. `.` у JS не збігається з `\r`, а `$` без прапорця `m` стоїть лише в кінці всього рядка — саме через це гейт CSP був червоний на Windows і зелений у CI |
| Новий видимий рядок у `src/routes/**` або `src/lib/components/**` — лише зі словника | `src/i18n-canon.test.ts` забороняє там кирилицю, і забороняє слушно: зашитий рядок означає 41 мову без перекладу. Єдиний виняток — сторінка чеклиста, і оформлений він переїздом тексту в `src/lib/data/betaChecklist.ts`, а не послабленням гейта |
| Обробник клавіш іде через `acceptsPageShortcut`, а не `acceptsShortcut` | другий не знає про вимикач гарячих клавіш, а вимикач — це WCAG SC 2.1.4 (рівень A) і CRITICAL у HOTKEYS-v8 § 3. Прямий виклик повз браму валить `src/lib/services/hotkeys.test.ts` |
| Файл із `OVERSIZED` у `src/structure.test.ts` не може вирости | там дев'ять файлів, що вже перевищують орієнтир § 7, і в кожного записана СТЕЛЯ. | Число боргу ESLint живе в мапі `DEBT` (`src/eslint-baseline.test.ts`), а не в коментарях | гейт звіряє його з прогоном ESLint В ОБИДВА боки: і коли борг виріс, і коли число застаріло після виправлення. Виправив попередження — опусти число тим самим комітом |
| Аксесор контексту мусить кидати | `getContext` віддає `undefined` мовчки, і падає воно не там, де причина. Тримає `src/context-conventions.test.ts` |

## Команди перевірки

```
npm run check       # svelte-check, має бути 0 помилок
npm run lint        # eslint; 0 errors, попередження — борг, що лише спадає
npm run test:unit   # Vitest
npm run build       # збірка
npm run check:build # інваріанти по build/ — запускати ПІСЛЯ build
```

`check:build` — єдиний гейт, що читає зібраний HTML. Клас дефектів, який він
ловить (мова сторінки, canonical, CSP, hreflang), у джерелах виглядає
правильним, тож `npm run check` і `test:unit` про нього не скажуть нічого.

**Результат треба побачити, а не припустити.** Твердження «правило виконано»
робиться після прогону, а не замість нього (AI-AGENT-PITFALLS-v8 § 5.1).
